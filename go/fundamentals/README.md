# go-fundamentals — основы Go вглубь на живом стенде

Примеры к мини-серии [«Основы Go вглубь»](https://khorost.tech/go/go-interfaces/) на khorost.tech. Это **не полный курс основ Go**, а узлы базового языка, где спотыкаются чаще всего: **интерфейсы, ошибки, слайсы и карты, методы и ресиверы**. Темы вроде пакетов/модулей, тестирования, конкурентности — отдельные материалы.
Чистый Go, без docker, только stdlib. Один модуль `tech.khorost/go-fundamentals-cookbook`, подкаталоги — по темам серии.

Идея стенда: **корректное поведение и инварианты покрыты тестами (`go test ./...` всегда зелёный), а наглядные «сюрпризы» и намеренные падения вынесены в отдельные запускаемые демо** `cmd/*` — их запускают руками, чтобы своими глазами увидеть ловушку или сообщение рантайма. Поэтому «сломанное» не мешает suite.

## Запуск

    # весь модуль: сборка, vet, тесты
    go build ./...
    go vet ./...
    go test ./...

    # демо-ловушки (запускать вручную, см. таблицу ниже)
    go run ./errors/cmd/typed-nil
    go run ./slices-maps/cmd/append-aliasing
    go run ./methods/cmd/receiver-copy

    # бенчмарк диспетчеризации (числа снимайте у себя — в стенде их намеренно нет)
    go test -bench=BenchmarkDispatch -benchmem -run=^$ ./interfaces/

## Что где

| Подкаталог | Тема | Содержимое (тесты = корректность) |
|---|---|---|
| [`errors/`](errors) | Обработка ошибок | sentinel `ErrNotFound`, обёртывание `%w`, `errors.Is`/`errors.As` сквозь цепочку, `errors.Join`; демо typed-nil и panic/recover — в `cmd/` |
| [`interfaces/`](interfaces) | Интерфейсы | маленький интерфейс + неявное удовлетворение, «accept interfaces, return structs», type switch; бенч прямой вызов vs через itab; демо nil-интерфейса — в `cmd/` |
| [`slices-maps/`](slices-maps) | Слайсы и карты | рост `append` (len/cap), nil vs пустой слайс, копия через `append(nil, …)`/`slices.Clone`; чтение/запись nil-карты (тест с recover); демо алиасинга, порядка map и concurrent map writes — в `cmd/` |
| [`methods/`](methods) | Методы и ресиверы | value- против pointer-ресивера (мутация копии не видна, оригинала — видна), method set и удовлетворение интерфейса (`*Doc` реализует `Stringer`, `Doc{}` — нет), method value и method expression; бенч цены копирования ресивера; демо потери мутации на большой структуре — в `cmd/` |

## Демо-ловушки (запускать вручную)

Эти программы показывают поведение, которое легко упустить, читая только корректный код:

| Команда | Что увидите (сверено живьём) |
|---|---|
| `go run ./errors/cmd/typed-nil` | `err != nil` истинно, хотя внутри интерфейса — nil-указатель: интерфейс = пара (тип, значение), тип не nil |
| `go run ./errors/cmd/panic-recover` | паника в функции перехвачена `defer recover()` и превращена в `error`; печатает восстановленное сообщение, процесс не падает |
| `go run ./interfaces/cmd/nil-interface` | `*T`(nil) в интерфейсной переменной != nil-интерфейс; печатает сравнение и объяснение (type != nil ⇒ interface != nil) |
| `go run ./slices-maps/cmd/append-aliasing` | два слайса делят backing-массив; `append` при запасе ёмкости МОЛЧА перезаписывает данные «соседа»; показан и безопасный вариант `s[:2:2]` |
| `go run ./slices-maps/cmd/map-order` | порядок обхода `map` меняется между проходами (рантайм рандомизирует; вероятностно — отдельные проходы могут совпасть); внизу — детерминированный обход через сортировку ключей |
| `go run ./slices-maps/cmd/concurrent-map` | **процесс аварийно завершается намеренно:** `fatal error: concurrent map writes` (exit != 0). Это не паника — `recover` её не ловит. Как чинить: `sync.Mutex`/`sync.Map` (см. соседний стенд `go-concurrency`, раздел `sync`) |
| `go run ./methods/cmd/receiver-copy` | метод с value-ресивером на большой структуре (`[256]int` внутри) «мутирует» поля, но правки МОЛЧА теряются — метод получил копию; печать до/после показывает потерю. Рядом — как чинить: тот же метод на pointer-ресивере правит оригинал |

> Все демо, кроме `concurrent-map`, завершаются штатно. `concurrent-map` падает **специально** — так рантайм показывает небезопасный конкурентный доступ к встроенной карте.

## Числа диспетчеризации (сверено)

Бенч `interfaces/dispatch_test.go` на `go1.26.3 windows/amd64` (`-benchmem -count=3`, ориентировочно, машинозависимо):

| Бенчмарк | ns/op | allocs | Что показывает |
|---|---|---|---|
| `BenchmarkDispatchDirect` | ~0.48 | 0 | прямой вызов метода конкретного типа (инлайн) |
| `BenchmarkDispatchMono`   | ~0.49 | 0 | интерфейс с ОДНИМ статически известным типом — компилятор **девиртуализирует**, ≈ прямому |
| `BenchmarkDispatchPoly`   | ~1.9  | 0 | полиморфный call-site (несколько типов) — реальный вызов через **itab**, ~4× дороже, без инлайна |

Вывод: интерфейс не «автоматически дорого». Go **девиртуализирует** мономорфные call-site (Mono ≈ Direct); цена itab-диспетчеризации проявляется на настоящих полиморфных вызовах (Poly). Аллокаций нет — значения указательные, боксинг был бы у value-типов.

## Числа копирования ресивера (сверено)

Бенч `methods/receiver_bench_test.go` (тип `heavy` с `[256]int` внутри, `go1.26.3 windows/amd64`, ориентировочно):

| Бенчмарк | ns/op | allocs | Что показывает |
|---|---|---|---|
| `BenchmarkReceiverValue`   | ~26   | 0 | value-ресивер копирует всю структуру (`[256]int`, ~2 КБ) на каждый вызов |
| `BenchmarkReceiverPointer` | ~0.27 | 0 | pointer-ресивер копирует только указатель — ~100× дешевле |

Аллокаций нет в обоих (копия на стеке); цена value-ресивера — в самом копировании крупной структуры. На мелких типах разница исчезает — value-ресивер там нормален.

## Версии

Проверено 2026-07 на **Go 1.26.3** (локально): `go build/vet/test ./...` зелёные, все демо-ловушки воспроизводятся, `concurrent-map` роняет процесс с `fatal error: concurrent map writes`.
Модуль объявляет `go 1.25.0` — это **минимальная** версия модуля; числа и выводы сверялись на **Go 1.26.3**. Зависимостей нет — только стандартная библиотека (`errors`, `fmt`, `slices`, `sort`, `sync`).

| Go (контейнер) | golang:1.26 |
| Модуль (`go.mod`) | go 1.25.0 |
| Зависимости | нет (stdlib) |
