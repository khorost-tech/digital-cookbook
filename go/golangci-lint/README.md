# go/golangci-lint — golangci-lint v2 счётом находок

Стенд к статье [«golangci-lint вглубь: линтеры Go как инструмент, а не галочка»](https://khorost.tech/go/go-golangci-lint/).
golangci-lint v2.14.0 в образе по дайджесту (`images.json`), на хост ничего не
ставится. Каждая ось считает **находки по разметке**: ожидаемая диагностика помечена
`// want <линтер>` на своей строке (на одном месте их бывает две — один дефект
видят два линтера), шум на исправном по смыслу коде — `// noise <линтер>`;
находка засчитывается, только если совпали файл, строка и линтер. Считаются и
диагностики, и места. У каждого дефекта есть исправленная пара в `fixed/`, на
которой линтер молчит. Что разметка верна по смыслу, а не только по правилу,
для части примеров доказывает тест поведения (`semantics/`).
Скорость прогона не публикуется.

Рядом — тренажёр `trainer/`: четыре уровня, которые читатель чинит сам до
зелёного прогона (свой README).

## Что внутри

```
sample/       дефекты по классам (errs, httpx, db, sec, vet, dead, perf)
fixed/        исправленные пары
trunc/        пакеты для опыта с обрезкой вывода
excl/         дефект в тесте и в сгенерированных файлах; danger/ — те же правила
              на настоящих дефектах (вход из запроса, Close после записи)
semantics/    тесты поведения: фиктивный драйвер database/sql, json.Encoder
nolint/       шесть форм //nolint
legacy/       build-repo.sh — git-репозиторий для --new-from-*
ctx/          код для своего правила
analyzer/     правило ctxloss на go/analysis + analysistest; plugin/ — module plugin
.custom-gcl.yml  сборка своего бинаря golangci-lint с ctxloss
configs/      .golangci.yml v2 на каждый прогон
trainer/      тренажёр L1–L4
scripts/      раннеры осей, разборы с контролями, проверки, реестр диверсий
fixtures/     замеры *.jsonl; manifests/ — сводки сессий; RUN-COMPLETE — маркер
expected.json гипотезы, записанные до прогона, и факты проб
```

## Как прогнать

Нужны Docker и Python 3.8+. Go и golangci-lint — в образе.

```sh
bash scripts/run-all.sh                     # всё разом, маркер последним
```

Один вариант — одной командой (её показывает статья):

```sh
python3 scripts/run-default.py curated      # оси 1–2: набор по умолчанию, курируемый, «всё»
python3 scripts/run-truncate.py many default   # ось 3: обрезка вывода
python3 scripts/run-exclude.py preset-std-error-handling   # ось 4: исключения v2
python3 scripts/run-nolint.py strict two-bare  # ось 5: //nolint и nolintlint
python3 scripts/run-legacy.py new-from-rev  # ось 6: легаси
python3 scripts/run-custom.py custom        # ось 7: своё правило (собирает свой бинарь)
python3 scripts/run-semantics.py TestSampleFirstHoldsConnection   # ось 8: смысл разметки
python3 scripts/run-trainer.py l3 start     # тренажёр: старт красный
```

Сам линтер — той же командой, что в строке `lint_cmd` фикстуры, например:

```sh
docker run --rm -v "$PWD":/src -w /src golangci/golangci-lint:v2.14.0 \
    golangci-lint run -c configs/curated.yml --max-same-issues 0 \
    --max-issues-per-linter 0 --uniq-by-line=false ./sample/...
```

Проверки и диверсии:

```sh
python3 -m unittest discover -s scripts -p "test_*.py"
python3 scripts/sabotage.py         # каждая проверка обязана покраснеть от своей поломки
```

## Что замерено

Подробности и сырые выводы — в `fixtures/`; две сессии полного прогона совпали
по опубликованному (`fixtures/manifests/`), вторая — с очищенным кешем линтера:
кеш на результат не влияет.

**Оси 1–2 — что ловит набор** (`default.jsonl`). В `sample/` 20 ожидаемых
диагностик на 18 местах. Класс места — метка `// kind`: 15 — ошибки
относительно контракта в комментарии функции, 1 — мёртвый код (unused), 2 —
предложения оптимизации (prealloc, perfsprint). Набор по умолчанию (`standard`: errcheck, govet,
ineffassign, staticcheck, unused) выдаёт 7 диагностик на 5 местах (4 ошибки и
мёртвый код): не видит
bodyclose, rowserrcheck, sqlclosecheck, errorlint, gosec, noctx, prealloc,
perfsprint, gocritic — и анализаторов `shadow` и `nilness`, выключенных внутри
самого govet. Курируемый `configs/curated.yml` находит все 18 мест, шум погашен
узко (по типу, по файлу с записанным допущением, по тексту), лишнего ноль.
`--default all` находит 16 мест — shadow и nilness он тоже не включает — и даёт
66 находок вне разметки, в основном от линтеров оформления. Исправленные пары
под курируемым конфигом — ноль находок.

**Ось 3 — обрезка вывода** (`truncate.jsonl`). По умолчанию golangci-lint
показывает не больше 3 находок с одинаковым текстом, 50 находок одного линтера
и одну находку на строку: 3 из 5, 50 из 60, 1 из 2. У errcheck текст для вызова
локальной функции не содержит её имени — 60 разных вызовов показаны как 3.
Код выхода во всех случаях 1. Все прогоны стенда — с
`--max-same-issues 0 --max-issues-per-linter 0 --uniq-by-line=false`.

**Ось 4 — исключения v2** (`exclude.jsonl`). На конфиге без исключений:
пресет `std-error-handling` прячет 5 настоящих дефектов — непроверенный
`os.Remove` и `Close` после записи — вместе с непроверенными `Close` на чтении; `common-false-positives` —
gosec G304; `legacy` — gosec G104; `comments` на этом коде не прячет ничего.
Правило по пути прячет дефект в `_test.go`. `generated: lax` не линтует ни файл
со стандартным заголовком `Code generated … DO NOT EDIT.`, ни файл с
нестандартным; `strict` — только первый. Прежний курируемый конфиг с широкими
исключениями (G107/G304 на проект, `(io.Closer).Close`) прячет `Close` после
записи; узкий — ничего. URL и путь из запроса широкие исключения не спрятали:
на них в gosec 2.14 срабатывают G704 и G703 (отслеживание данных из запроса),
а не G107 и G304.

**Ось 5 — `//nolint`** (`nolint.jsonl`). Директива подавляет находку названного
линтера; `//nolint:noctx` на строке с находкой errcheck её не подавляет.
nolintlint (`require-specific`, `require-explanation`, `allow-unused: false`)
отмечает голую директиву, директиву без причины и неиспользуемую. Голый
`//nolint` на строке с двумя дефектами прячет оба, а nolintlint говорит только о
форме директивы.

**Ось 6 — легаси** (`legacy.jsonl`). Репозиторий: main со старым кодом (3
дефекта в двух файлах), feature — правка строки старого дефекта и новый дефект.
Полный прогон — 4; `--new-from-rev=HEAD~1` и `--new-from-merge-base=main` — 2:
новый и старый на изменённой строке; `--whole-files` — 3, весь изменённый файл.

**Ось 7 — своё правило** (`custom.jsonl`). `ctxloss` — `context.Background()`/
`TODO()` в функции, которая уже получила `context.Context` (и через алиас
`type Ctx = context.Context` — его снимает `types.Unalias`; и внутри литерала
функции со своим `ctx`). Граница: правило смотрит на место создания и не
отслеживает корневой контекст, созданный там, где параметра-контекста нет. analysistest с
отрицательными случаями проходит; свой бинарь `golangci-lint custom` находит 5
функций из 5 и ни одной лишней. `contextcheck` находит 3 — не видит корневой
контекст, который не передан дальше (ожидание `<-bg.Done()`, поле структуры), и
ставит находку туда, где контекст использован; `noctx` — 0, он о другом.
Обычный бинарь с конфигом, где включён ctxloss, отказывается запускаться.

**Ось 8 — смысл разметки** (`semantics.jsonl`). Фиктивный драйвер
database/sql с одним соединением: полный проход `rows.Next()` без `Close`
освобождает соединение (контроль), ранний выход `sample/db.First` без `Close` —
держит, `fixed/db.First` — освобождает. `json.Encoder.Encode(chan int)` падает до
записи: тело пустое, статус 500 ещё выставляется. Контракты из комментариев:
`Merge` в `sample/` делит память с `a`, `Normalize` не обрезает пробелы —
исправленные пары контракт выполняют; `IDs` на пустом входе даёт `null` и в
`sample/`, и в `fixed/`, а наивное исправление prealloc
(`make(…, 0, len)`) — `[]`. Зелёный линтер доказывает выполнение правил, а не
исправность программы; исправление замечания тоже требует проверки контракта.

**Тренажёр** (`trainer.jsonl`). Каждый уровень на старте красный, на эталоне
`trainer/solutions/` зелёный; у каждого замечания старта есть подсказка.

## Чего эти числа не значат

- **Ничего о скорости.** Один проход загрузки пакетов и кеш — свойство
  golangci-lint, но здесь не измерены.
- **Версия:** golangci-lint 2.14.0 (Go 1.27.1). Набор по умолчанию, тексты
  находок, пресеты и эвристики линтеров (gosec G101 зависит и от значения
  строки) — свойства этой версии; с другой версией числа будут другими, поэтому
  версия закреплена по дайджесту.
- **Разметка — мнение автора стенда** о том, что дефект, а что шум, при его
  допущениях: URL и путь в `sample/` приходят от доверенного вызывающего, `Close`
  тела ответа — после чтения. Поведением подтверждены только примеры оси 8; в
  другом проекте граница может проходить иначе.
