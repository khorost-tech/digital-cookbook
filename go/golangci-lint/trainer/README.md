# Тренажёр golangci-lint: почини сам

Четыре уровня. В каждом — код с замечаниями линтера; задача — довести уровень до
PASS. Грейдер запускает golangci-lint той же версии, что стенд (образ по
дайджесту из `../images.json`), и на каждое замечание печатает, что оно значит и
куда смотреть.

Нужны Docker и Python 3.8+.

```sh
./check.sh l1          # проверить уровень
```

Уровни лучше проходить по порядку: каждый следующий опирается на предыдущий.

| уровень | что внутри |
|---|---|
| `l1` | непроверенная ошибка, незакрытое тело ответа, присваивание, которое ничего не меняет |
| `l2` | секрет в коде, `math/rand` для идентификатора сессии, непроверенный `rows.Err()`, затенённая ошибка |
| `l3` | замечание, которое нужно **подавить** узко и с причиной, а не переписать; дефект, которого текущий конфиг не видит, — включить нужный линтер в `l3/.golangci.yml` и починить |
| `l4` | своё правило: дописать анализатор `l4/rule` на `go/analysis`; проверка — `analysistest` |

## Правила

- Чините код, а не конфиг: отключить линтер в `.golangci.yml` — не решение (кроме
  задачи L3 «включить нужный линтер»).
- Подавление — только там, где об этом просит задача, и только узкое:
  `//nolint:<линтер> // причина`. Голый `//nolint` уровень не примет.
- Эталон — в `solutions/`; свериться: `./check.sh l2 --dir solutions/l2`.

## Чем отличается от стенда

Стенд (каталог выше) **показывает**: считает, что находят разные конфиги, на
размеченных дефектах. Тренажёр **тренирует**: читатель сам доходит до
зелёного прогона. Стенд проверяет тренажёр: каждый уровень на старте красный,
на эталоне зелёный, у каждого замечания есть подсказка (`fixtures/trainer.jsonl`).
