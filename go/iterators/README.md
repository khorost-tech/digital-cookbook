# go-iterators — range-over-func и пакет iter на живом стенде

Примеры к статье [«Итераторы в Go: range-over-func и пакет iter»](https://khorost.tech/go/go-iterators/) на khorost.tech.
Чистый Go, без docker, только stdlib (`iter`, Go 1.23). Модуль `tech.khorost/go-iterators-cookbook`.

Идея стенда: **поведение итераторов — композиция, ранний break, очистка — покрыто тестами**; наглядную гарантию очистки при break показывает демо `cmd/break-cleanup`; цену абстракции — бенчи.

## Запуск

    go build ./...
    go vet ./...
    go test ./...

    go run ./cmd/break-cleanup                       # cleanup срабатывает при break
    go test -bench=. -benchmem -run=^$ ./seq/         # цена range-over-func

## Что где

| Подкаталог | Тема | Содержимое |
|---|---|---|
| [`seq/`](seq) | Пуш-итераторы | `iter.Seq`/`iter.Seq2`: `Count`, `Filter`, `Map`, `Enumerate`, `WithCleanup` (очистка через `defer`), `Collect`; ранний break обрывает выдачу |
| [`pull/`](pull) | Пул-итераторы | `iter.Pull`: `Zip` (два источника «в ногу»), `Take` (первые n без материализации миллиона) — то, что одним `range` не выразить |

## Демо (`go run ./cmd/break-cleanup`, сверено)

Итератор держит ресурс (`defer cleanup`). Читатель прерывает обход `break` на 3-м элементе — **cleanup всё равно выполняется**: `range` передаёт итератору `false` из `yield`, тот выходит и разматывает `defer`. Поэтому файлы, строки БД, соединения можно закрывать внутри итератора.

## Числа: цена абстракции (сверено)

`seq/bench_test.go`, сумма `0..999` за проход, на `go1.26.3 windows/amd64`, ориентировочно:

| Бенчмарк | ns/op | allocs | Что показывает |
|---|---|---|---|
| `BenchmarkPlainLoop`   | ~260  | 0 | голый `for i` — эталон |
| `BenchmarkSliceRange`  | ~340–420 | 0 | `range` по слайсу |
| `BenchmarkSeqRange`    | ~2300 | 0 | `range` по `iter.Seq` — каждый элемент это вызов `yield` |
| `BenchmarkSeqFilterMap`| ~6500 | 5 (104 B) | конвейер `Filter`+`Map` через итераторы, один проход без промежуточных слайсов; аллокации — замыкания конвейера |

Честный вывод: **«итератор бесплатен» — миф.** На тривиальном теле (сложение) `range-over-func` в разы дороже голого цикла — накладной расход на каждый элемент это вызов функции-`yield`. Конкретная кратность машинозависима: на go1.26.3 windows/amd64 получилось ~9×, на Linux/AMD в тех же условиях ближе к ~3× (PlainLoop ~1280 vs SeqRange ~4020 ns). Не берите «девять раз» за константу — снимайте свои числа. Относительная цена тает, когда тело делает реальную работу (парсинг, I/O, вычисление): там пара наносекунд на элемент теряется в общем времени. Итераторы берут ради **читаемости и композиции** (ленивые конвейеры без промежуточных слайсов, единый интерфейс обхода), а не ради скорости. В горячем счётном цикле оставляйте обычный `for`.

## Версии

Проверено 2026-07 на **Go 1.26.3** (локально): тесты зелёные, демо и бенчи воспроизводятся. Модуль объявляет `go 1.25.0` (минимум; `range`-over-func и `iter` — с Go 1.23). Зависимостей нет — только `iter`.
