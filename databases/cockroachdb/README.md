# Стенд CockroachDB

Живой кластер CockroachDB и шесть сценариев к серии «CockroachDB: глубокое погружение»
на [khorost.tech](https://khorost.tech/databases/cockroachdb-architecture-ranges-raft/).

Стенд отвечает на один вопрос: **как получается serializable SQL на масштабе** — и даёт
числа, а не пересказ документации. Всё, что попало в статьи, лежит в
[`FIXTURES.md`](FIXTURES.md) вместе с версией, топологией и оговорками.

## Требования

- Docker с compose. **Поднимать из WSL2**, не из Windows-оболочки.
- Свободные порты хоста: `15436-15438` (SQL), `18080-18082` (DB Console).
  Профиль `05-geo` дополнительно занимает `15440-15448` и `18090-18098`.
- Около 6 ГБ памяти под базовый профиль, до 12 ГБ под `05-geo`.

### Ловушка WSL2 + Docker Desktop

`docker compose pull` из WSL падает с `docker-credential-desktop.exe: executable file
not found in $PATH`: конфиг Docker ссылается на Windows-хелпер, которого нет в PATH
внутри WSL. Лечится добавлением каталога Docker Desktop в PATH перед запуском:

```bash
export PATH="$PATH:/mnt/c/Program Files/Docker/Docker/resources/bin"
```

## Лицензия и телеметрия — прочитать до запуска

С версии 24.3 у CockroachDB нет self-hosted Core: осталась одна редакция, бесплатная
для физлиц и компаний с выручкой ниже 10 млн долларов, но требующая ключа и телеметрии.

- **Многоузловой кластер без лицензионного ключа работает 7 дней**, после чего
  троттлится до 5 одновременных SQL-транзакций.
- Одноузловой dev-кластер ключа не требует.
- Телеметрия на бесплатной лицензии обязательна и отключению не подлежит — кластер
  ходит наружу, на эндпоинт вендора.

Стенд эфемерный и в грейс укладывается: ключ не заводится. Троттлинг после грейса
здесь не измеряется — для этого пришлось бы ждать неделю.

## Как поднять

```bash
bash scripts/up.sh      # три узла, инициализация, схема
bash scripts/probe.sh   # фактические версии, лицензия, настройки
bash scripts/down.sh    # снести всё вместе с томами
```

После `up.sh`: SQL на `postgresql://root@127.0.0.1:15436/bank?sslmode=disable`,
DB Console на `http://127.0.0.1:18080`.

## Сценарии

| Скрипт | Статья | Что меряет |
|---|---|---|
| `scripts/probe.sh` | все | версия, состояние лицензии, уровень изоляции, границы zone config |
| `scripts/01-ranges.sh` | Архитектура | распределение реплик, split под нагрузкой, переезд leaseholder |
| `scripts/02-time.sh` | MVCC и HLC | uncertainty restarts, follower reads, глубина `AS OF SYSTEM TIME` |
| `scripts/03-txn.sh` | Транзакции | contention, доля retry, влияние формы первичного ключа |
| `scripts/04-sql.sh` | SQL-слой | локальный против распределённого плана, индекс, статистика |
| `scripts/05-geo.sh` | Геораспределение | survival goals, follower reads, гео-партиционирование |
| `scripts/06-ops.sh` | Эксплуатация | rolling upgrade, бэкап и восстановление, миграция PG-схемы |

Нагрузку генерирует `loadgen/` (Go, `pgx/v5`): режимы вставки, contention на горячей
строке и чтения, корректный retry-цикл по `SQLSTATE 40001`, перцентили задержек.

## Оговорки

- «Регионы» в `05-geo` — это метки `--locality`, и **межрегиональных задержек в стенде
  нет**. Эмулировать их не удалось: ядро WSL2 собрано без планировщиков трафика
  (`tc netem` и `prio` отсутствуют, каталога модулей нет). Скрипт сам измеряет и
  печатает фактический RTT между «регионами» — на этой машине 0.088–0.101 мс.
  Поэтому профиль меряет **механику размещения** (число и раскладку голосующих реплик,
  привязку строки к региону шлюза), а не цену расстояния.
- Числа сняты на одной машине под Windows 11 + WSL2. Абсолютные величины зависят от
  железа; смысл имеют соотношения между режимами, а не сами значения.
