# Что и почему мерим

Bench-харнес (`bench/go`) — единственный источник чисел-эталона для статьи. Он гоняет
одни и те же пять графовых вопросов на трёх углах (Neo4j, Apache AGE, honest baseline
на рекурсивных CTE) по осям, на которых углы расходятся по делу, а не случайно.

## Честность замера

- **Прогрев вне таймера.** Первый прогон каждого (сценарий, backend) не входит в результат —
  прогреваются кэши страниц PostgreSQL и page cache Neo4j.
- **Медиана из нескольких повторов.** Берётся медиана, а не среднее — устойчивее к выбросам.
- **Фиксированный seed датасета.** Граф детерминирован (`dataset --seed 42`), числа
  воспроизводимы между прогонами.
- **Один harness.** Все три угла меряются одним кодом на Go — числа сравнимы. Java/Rust-клиенты
  показывают паритет ответов, но не числа (другие драйверы → несопоставимо).
- **Таймаут — это данные.** Где угол не укладывается в границу (по умолчанию 30 с), пишется
  `timeout`, а не выдуманное число. Расхождение — сигнал искать артефакт замера
  ([[measurement-cache-traps]]), а не готовый вывод.

## Оси

| Сценарий | Ось | Что показывает |
|---|---|---|
| `access` | фиксированная форма | базовая стоимость короткого обхода прав (2–3 hops) |
| `impact_depth=1..8` | **глубина traversal** | где рекурсивный CTE начинает проигрывать нативному обходу |
| `cyclic_maxLen=5..15` | граница длины цикла | стоимость обнаружения циклов зависимостей |
| `distance_maxLen=4..8` | **граница пути** | обрыв AGE: без `shortestPath` var-length перебирает все пути до границы |
| `ring_length=3,4` | **fan-out** | fraud-кольца: дорогой обход с ветвлением |

## Что ожидаем (и что проверяем санити-чеком)

- На мелкой глубине (`impact_depth=1..2`, `cyclic_maxLen=5`) baseline-CTE **конкурентен или
  быстрее** нативной графовой БД: на индексированных FK PostgreSQL закрывает вопрос без
  отдельного storage tier. Если baseline тут медленный — значит не сработали индексы
  (`dataset/schema.sql`), а не модель.
- На глубоком traversal и высоком fan-out (`impact_depth=8`, `ring_length`) разрыв растёт
  в пользу нативного обхода Neo4j.
- **AGE проседает на `distance`**: у AGE 1.6 нет `shortestPath()`, эмуляция через
  `MATCH p=(a)-[*1..N]-(b) RETURN length(p) ORDER BY length(p) LIMIT 1` перебирает все пути
  до границы N, поэтому стоимость растёт с N, а не с фактическим расстоянием.

## Ось объёма

Ось «объём данных» снимается запуском на двух масштабах: прогнать bench на дефолтном графе,
затем перегенерировать крупнее и прогнать снова.

```bash
# ×1 (дефолт)
cd dataset && go run . --seed 42 --out ./out && cd ..
# … загрузить (см. корневой README) и прогнать bench …

# ×~10 по узлам
cd dataset && go run . --users 20000 --teams 1500 --roles 2000 \
  --resources 8000 --services 3000 --packages 12000 --seed 42 --out ./out && cd ..
# … перезагрузить и прогнать bench снова, сравнить CSV …
```

Результаты — в `bench/out/results.csv`.
