### CockroachDB

- Atlas: `pq: unexpected transaction status idle`; при этом журнал
  `atlas_schema_revisions` создан, а таблица `probe` — нет.
- Alembic с диалектом `postgresql`: `Could not determine version from string
  'CockroachDB CCL v26.2.5 …'` — до миграций не доходит.
- goose, Flyway, Liquibase: применение и откат — как на PostgreSQL.

## Обходные пути для CockroachDB (`fixtures/10-workarounds-crdb.txt`)

- Новые таблицы создаются `WITH (schema_locked = true)`
  (`create_table_with_schema_locked = on`).
- Atlas с `options=-c autocommit_before_ddl=off`: первая миграция применилась,
  вторая — `this schema change is disallowed because table "probe" is locked and this
  operation cannot automatically unlock the table`, затем `write revision: current
  transaction is aborted`. С `--tx-mode file` — тот же отказ на второй миграции; с `--tx-mode none` — та же
  ошибка, что по умолчанию (`unexpected transaction status idle`).
- Alembic с `sqlalchemy-cockroachdb` 2.0.4: `upgrade head` и `downgrade -1` работают;
  `alembic check` находит фантомные изменения — `modify_type … VARCHAR() → Text()` для
  колонок `name` и `note`, хотя `information_schema` показывает `text`.

## Частичное применение (`fixtures/20-partial.txt`, `fixtures/partial.tsv`)

Вторая миграция: `ALTER TABLE probe ADD COLUMN note` + `INSERT INTO missing_table`.
Два прогона подряд; после каждого — схема и журнал.

| Инструмент × СУБД | probe / note после отказа | Журнал | Повтор |
|---|---|---|---|
| goose, Flyway, Liquibase, Atlas × PostgreSQL | есть / нет | только первая | та же ошибка |
| Alembic × PostgreSQL | **нет / нет** | таблицы журнала нет (одна транзакция на `upgrade head`) | та же ошибка |
| goose × CockroachDB | есть / **есть** | `1:true` | `column "note" of relation "probe" already exists` |
| Flyway × CockroachDB | есть / **есть** | `1:true 2:false` | `Validate failed … Detected failed migration to version 2` |
| Liquibase × CockroachDB | есть / **есть** | `1` | `column "note" of relation "probe" already exists` |

Flyway на CockroachDB помечает миграции `[non-transactional]` и при сбое пишет
`Please restore backups and roll back database and code!`.

## Восстановление на CockroachDB (`fixtures/21-recover-crdb.txt`)

Схема проверяется перед каждой командой согласования журнала.

- **Liquibase — довести до конца:** недостающая часть changeset выполнена руками
  (`CREATE TABLE missing_table`, `INSERT`), схема проверена (`1|1`),
  `mark-next-changeset-ran` — `executed successfully`, журнал `1:EXECUTED 2:EXECUTED`,
  `update` — `Run: 0`, `Previously run: 2`.
- **Flyway — вернуть исходное:** `ALTER TABLE probe DROP COLUMN note`, схема проверена
  (`0`), `repair` — `Successfully repaired schema history table`, журнал `1:true`;
  исправленная V2 (`tools/flyway/partial-fixed`) применилась, журнал `1:true 2:true`.

Команды миграторов в `recover.sh` и `probe.sh` идут без фильтров: фикстуры хранят
полный вывод и настоящий код возврата инструмента (ожидаемые отказы — код 1).
Сужение `grep`/`head` — только в листингах статьи.
