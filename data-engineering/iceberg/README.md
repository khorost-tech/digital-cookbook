# data-engineering/iceberg — «паркет в папке» против Iceberg

Стенд к статье [«Open table formats: Iceberg, Delta и Hudi поверх озера»](https://khorost.tech/databases/open-table-formats-iceberg-delta/).
На одном объектном хранилище — две таблицы с одними и теми же заказами (14
дней сентября 2026): «папка» — паркет-файлы, которые пишет и читает pyarrow, и
таблица Apache Iceberg. Над ними ставятся одни и те же действия, и считается
исход: сколько изменений потеряно, сколько строк увидел читатель, сколько строк
переписано ради одной удалённой. Время не публикуется.

## Что внутри

```
compose.yml       SeaweedFS 4.48 (S3), Iceberg REST catalog 1.10.1, Spark 4.1.3 + Iceberg 1.12.0,
                  tools (Python 3.12: PyIceberg 0.12, pyarrow 25, boto3)
s3/s3.json        учётка S3 — заведомо тестовая; без неё SeaweedFS отвергает подписанные запросы
generator/gen.py  заказы, фиксированное зерно
jobs/             задания: writers, reader, folder_ops, plan (tools); sp_delete, sp_schema,
                  sp_partitions, sp_maint (Spark)
scripts/          раннеры осей, разбор с контролями, проверки, диверсии
fixtures/         замеры; manifests/ — сводки сессий; RUN-COMPLETE — маркер
expected.json     гипотезы до прогона и факты проб
```

Опыты с двумя писателями и читателем ставятся **заданным чередованием**, а не
гонкой потоков: оба писателя читают одно состояние, затем пишут по очереди;
читатель смотрит в заданный момент записи.

## Как прогнать

Нужны Docker и Python 3.8+.

```sh
bash scripts/run-all.sh             # всё разом, маркер последним
FRESH=1 bash scripts/run-all.sh     # то же с пустых томов
python3 scripts/run-writers.py iceberg       # один вариант
python3 -m unittest discover -s scripts -p "test_*.py"
python3 scripts/sabotage.py
```

## Что замерено

Две сессии полного прогона (вторая — с пустых томов) совпали по
опубликованному (`fixtures/manifests/`).

**Ось 1 — два писателя** (`writers.jsonl`). Оба читают день 03.09 и меняют
разные строки. Папка: второй перезаписал файл — изменения первого потеряны все
(0 из 26). Iceberg: REST-каталог отверг коммит второго (снапшот сменился),
PyIceberg повторил его сам и при повторе отказал окончательно
(`ValidationException`: первый писатель добавил файлы под тот же фильтр
перезаписи); второй перечитал таблицу и повторил — на месте оба изменения.

**Ось 2 — читатель во время записи** (`reader.jsonl`). 4 файла новых строк,
чтение после 2-го: папка — 130 из 259 новых строк; Iceberg — 0, хотя два файла
данных уже лежат в хранилище; после коммита — все.

**Оси 3–4 — удаление и история** (`delete.jsonl`). Удаление одного заказа:
папка и copy-on-write переписывают файл дня (284 строки), merge-on-read — 0
файлов данных и 1 файл удалений. `VERSION AS OF` первого снапшота возвращает
исходные строки и статусы, `rollback_to_snapshot` — тоже; у папки истории нет.

**Ось 3б — физическое удаление** (`erase.jsonl`). Копии удалённой строки в
паркет-объектах таблицы: после `DELETE` — 1 в обоих режимах; после
`expire_snapshots` copy-on-write — 0, merge-on-read — 1 (файл данных текущий);
после `rewrite_data_files` и повторного истечения — 0.

**Ось 5 — схема** (`schema.jsonl`). Переименование колонки: в папке у 2076
старых строк значения под новым именем пусты, в Iceberg — на месте. Удаление и
повторное добавление колонки с тем же именем: в папке старые значения
«воскресают» у всех 2076, в Iceberg — пусто (новый идентификатор поля).

**Ось 6 — партиции** (`partitions.jsonl`). Смена партиционирования с дня на
месяц не переписала 7 старых файлов. Фильтр по времени заказа: Iceberg
планирует 1 файл из 8; папка с каталогами по дню — все 14 (по колонке каталога
— 1).

**Ось 7 — обслуживание** (`maintenance.jsonl`). 50 вставок по строке — 50
файлов и 50 снапшотов; `rewrite_data_files` — 1 файл, но старые 50 остаются в
хранилище; `expire_snapshots` — 1 снапшот, 1 объект данных. Прежние
`metadata.json` он не удаляет (объектов метаданных 105) — это отдельная
настройка `write.metadata.delete-after-commit.enabled`.

## Чего эти числа не значат

- **Ничего о скорости** запросов и записи.
- **Худший порядок шагов задан явно**; как часто он случается под нагрузкой,
  стенд не говорит.
- **Delta Lake и Hudi не измерены.**
- **Версии:** Iceberg 1.12.0, REST-каталог 1.10.1, PyIceberg 0.12.0, Spark 4.1.3,
  SeaweedFS 4.48, формат таблицы v2.
