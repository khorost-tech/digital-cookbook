# data-engineering/dimensional — звёздная схема против эталона

Стенд к статье [«Dimensional modeling: star schema, факты, измерения и SCD»](https://khorost.tech/databases/dimensional-modeling-warehouse/).
PostgreSQL 18 (база `dwh`: `app` — источник, как его отдаёт реплика,
`snapshots`, `staging`, `marts`) и контейнер `tools` с генератором и dbt-core
1.12 + dbt-postgres 1.11. Генератор строит магазин за 14 дней сентября 2026 с
событиями измерений и **сам** считает эталон по своей полной истории.
Хранилище строится по дням: состояние источника на конец дня → `dbt snapshot`
(SCD2) → модель SCD3; затем факты. Каждый отчёт сверяется с эталоном.

## Что внутри

```
generator/gen.py   источник и эталон: переезды клиентов, категории, склад,
                   переиспользованный id 77, поздний клиент 201
dbt/snapshots/     customers_snapshot — SCD2
dbt/models/marts/  dim_customer_scd1/2/3, dim_product, fct_order, fct_order_item, fct_inventory
scripts/           раннеры осей, разбор с контролями, проверки, диверсии
fixtures/          замеры; manifests/ — сводки сессий; RUN-COMPLETE — маркер
expected.json      гипотезы до прогона и факты проб
```

## Как прогнать

Нужны Docker и Python 3.8+.

```sh
bash scripts/run-all.sh             # всё разом, маркер последним
FRESH=1 bash scripts/run-all.sh     # то же с пустых томов
python3 scripts/run-scd.py asof-scd1         # один вариант
python3 -m unittest discover -s scripts -p "test_*.py"
python3 scripts/sabotage.py
```

## Что замерено

Две сессии полного прогона (вторая — с пустых томов) совпали по
опубликованному (`fixtures/manifests/`).

**Ось 1 — SCD** (`scd.jsonl`). 40 клиентов переезжают (30 раз, 10 дважды).
Выручка по региону на момент заказа: SCD2 по версии на момент заказа — эталон;
SCD1 и текущий регион SCD3 расходятся с эталоном в итогах по регионам на
2,90%, а по заказам приписывают не тому региону 451 заказ — 11,90% выручки:
встречные переносы между регионами в итогах гасятся. По текущему
региону человека SCD1 и SCD2 по бизнес-ключу ошибаются одинаково (0,12%) — на
заказы прежнего владельца id 77. Регион до первого переезда в SCD3 верен у всех
переехавших раз и неверен у всех переехавших дважды.

**Ось 2 — гранулярность** (`grain.jsonl`). Выручка по категории из факта
заказа, соединённого с позициями, — ×3,001 (сумма заказа повторена по числу
позиций, а дорогие заказы — с большим числом позиций); `count(*)` по факту
позиции вместо числа заказов — ×2,504.

**Ось 3 — аддитивность** (`additivity.jsonl`). Сумма дневных остатков склада за
неделю — ×7,31 к остатку последнего дня; среднее дневных долей отменённых —
×0,9937 к доле за период.

**Ось 4 — ключи** (`keys.jsonl`). 5 заказов клиента 201 до его появления в
источнике: внутреннее соединение с версией клиента теряет их выручку; левое с
«неизвестным участником» сохраняет итог без региона; переназначение на первую
версию — эталон. Переиспользованный id 77: через SCD1 новому владельцу
приписано 18 заказов, его собственных 8; через версию SCD2 на момент заказа — 8.

## Чего эти числа не значат

- **Ничего о скорости.** ~4 тысячи заказов; правильность отчётов, а не
  производительность.
- **Доли отклонений задаёт генератор** (доля переехавших, число позиций,
  размер дней); на других данных проценты другие, направление то же.
- **Снимки ежедневные:** изменения между снимками SCD2 не различает.
- **Версии:** dbt-core 1.12.5, dbt-postgres 1.11.0, PostgreSQL 18.6.
