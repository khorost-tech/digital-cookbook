# performance/load-testing — нагрузочное тестирование и хаос против сервиса-эталона

Стенд к статье [«Нагрузочное тестирование и chaos engineering»](https://khorost.tech/performance/load-testing-chaos/).

Эталон — не генератор, а сервис `svc` (Go): время обслуживания S = 10 мс, C = 8
обработчиков (ёмкость C/S = 800 запросов/с), расписание пауз (сервис не
начинает обслуживание P секунд из каждых T — аналог stop-the-world). Сервис
сам считает принятые запросы по секундам, время каждого, окна пауз и отдельно
занятость обработчика — без ожидания в очереди (`/admin/stats`). Для открытой модели истина считается заранее —
`scripts/truth.py` детерминированно симулирует тот же сервис.

## Оси

| ось | что | раннер |
|---|---|---|
| model | одна задача (200/с или 3 соединения, 60 с, пауза 1 с из 10 с) — 13 режимов восьми генераторов против истины | `scripts/run-model.py` |
| types | k6: load, stress, spike (и spike без запаса VU), soak на сервисе с утечкой — против расчёта | `scripts/run-types.py` |
| ceiling | `/fast` на 1000–16 000/с: где генератор перестаёт держать темп; закрытые — сколько выжимают; ЦП генератора — отдельными прогонами `+cpu`, медиана за интервал нагрузки (опрос `docker stats` сам нагружает VM) | `scripts/run-ceiling.py` |
| chaos | две реплики за HAProxy, зависимость за Toxiproxy: задержка, отказ, остановка реплики; наивный и устойчивый сервис (запасной ответ — последняя цена и её возраст); abortOnFail; полная операция (op_duration) рядом с http_req_duration; окно сбоя, снятие и худшая секунда по сырым точкам k6; журнал HAProxy | `scripts/run-chaos.py` |

Генераторы: wrk, wrk2, vegeta, oha, hey (образ `tools/Dockerfile.gen`), k6,
Gatling (Maven, `gatling/`), Locust. Все — одноразовыми контейнерами
`docker compose run` с одинаковым лимитом: 2 ЦП, 1 ГБ.

## Запуск

```bash
bash scripts/run-all.sh             # полный прогон: ≈ час
FRESH=1 bash scripts/run-all.sh     # то же с пересборкой образов и пустыми томами
python3 scripts/run-model.py hey vegeta   # отдельные варианты, без записи фикстуры
python3 scripts/truth.py 200 60 1 10      # истина открытой модели
```

Нужны Docker с compose и Python 3. Первая сборка образа генераторов — около
10 минут (oha собирается из исходников).

## Что внутри

```
svc/                 сервис-эталон (Go) и его тесты
tools/               Dockerfile.svc, Dockerfile.gen (wrk2 на arm64 — с правками, см. комментарий)
scenarios/           k6 (model, types, chaos), Locust, lua-отчёт wrk/wrk2
gatling/             Maven-проект Gatling (симуляция stand.Model)
config/              HAProxy (с повторами и без), Toxiproxy
scripts/             раннеры осей, truth.py, analyze.py, проверки, диверсии, сводки
fixtures/            замеры *.jsonl; manifests/ — сводки сессий; RUN-COMPLETE — маркер
expected.json        гипотезы до прогона и что вышло на самом деле
images.json          образы по дайджесту
```

Команда генератора для каждой строки фикстуры — поле `tool_cmd`; её можно
выполнить в каталоге стенда, подняв сервис (`docker compose up -d svc`).

## Ограничения

Всё — в одной VM Docker Desktop: генератор и сервис делят хост, и мгновенная
пауза хоста видна открытому генератору как задержка (так и должно быть, но
контролю модели поэтому дана одна повторная попытка). Потолки генераторов —
для 2 ЦП контейнера на этой машине, не абсолютные.
