# Rust async: Tokio на практике

Companion-демо к статье [«Rust async runtime: Tokio изнутри»](https://khorost.tech/rust/rust-async-tokio/)
(серия «Rust для backend»).

Три сюжета из статьи, воспроизводимые **оффлайн и детерминированно** — без сети и внешних сервисов:

| Сюжет | Что показывает |
|-------|----------------|
| `concurrent_io` | `tokio::join!` + `timeout` — две «I/O-операции» по 50 мс идут конкурентно (~50 мс, а не 100), таймаут отменяет медленный future |
| `cpu_offloaded` | `spawn_blocking` — тяжёлая синхронная CPU-работа мимо async-планировщика |
| `backpressure`  | ограниченный `mpsc::channel(4)` — `send().await` тормозит producer'а, когда буфер полон |

## Запуск

```bash
cargo run
```

Пример вывода (числа времени зависят от машины):

```
[join] a=5 b=4 за 50.4ms — конкурентно, а не последовательно (иначе было бы ~100 мс)
[timeout] операция отменена по таймауту — медленный future дропнут
[spawn_blocking] CPU-результат=1249999975000000 — посчитан вне async-планировщика
[backpressure] consumer обработал 10 сообщений через канал ёмкостью 4
```

## Сетевой пример (нужен доступ в интернет)

Параллельные HTTP-запросы с таймаутом — ровно тот код, что во врезке статьи:

```bash
cargo run --example parallel_http
```

## Проверка

```bash
cargo run                          # оффлайн-демо
cargo check --example parallel_http # сетевой пример (компиляция без запроса)
```

Проверено на стабильном Rust (edition 2021), `tokio = "1"`. Внешних сервисов основной демо не требует.
