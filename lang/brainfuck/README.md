# brainfuck: интерпретатор и замер разрыва выразительности

Стенд к статье [«Тьюринг-полнота и выразительность»](https://khorost.tech/lang/turing-completeness-and-expressiveness/).

Две вещи на одном коде:

1. **Интерпретатор brainfuck на Go** (`interp.go`, ~110 строк) — универсальная
   машина размером с один экран: одна программа исполняет любой brainfuck.
   (Тьюринг-полнота самого brainfuck — отдельный результат, к которому это
   опора, а не доказательство.)
2. **Замер разрыва выразительности** — одна задача, решённая дважды (brainfuck и
   Go), с числами, снятыми из исходников, а не из головы.

## Запуск

```bash
go test ./...                              # интерпретатор + эквивалентность версий
go test -run ExpressivenessGap -v ./...    # таблица разрыва
```

## Как замер держится честным

Сравнивать размер двух программ можно, только если они делают одно и то же.
Поэтому каждая задача в `gap.go` задана дважды — как brainfuck-строка и как
Go-функция, — а `TestEquivalence` **прогоняет обе на одном входе и сверяет
вывод**. Пока тест зелёный, версии эквивалентны по вычислению, и разошлись они
только в выразительности.

Числа тоже не вписаны руками:

- команды brainfuck считаются по самой программе (8 символов, остальное —
  комментарий);
- размер и «именованность» Go меряются `go/parser`-ом **прямо по `gap.go`** —
  замеряется ровно тот код, что исполнялся в тесте, разойтись они не могут.

## Что показал замер

```
задача                             bf-команд Go-симв.   bf/Go    Go имён  bf имён bf циклов
эхо ввода (cat)                           5       30   0.17          9        0        1
удвоить байт (a → 2a)                    10      100   0.10         13        0        1
сложить два байта (a,b → a+b)            11      107   0.10         13        0        1
напечатать «Hello World!\n»             106       51   2.08          8        0        3
```

Наивная гипотеза была «brainfuck многословен» — и замер её **опроверг**. На
арифметике brainfuck в разы КОРОЧЕ Go (0.10–0.17 от его символов): у Go уходят
строки на обработку ошибок и возню с байтами, а `[-<+>]` складывает два числа
одиннадцатью символами. Раздувается brainfuck только на «Hello World» (2× по
символам), и то по частной причине — константу-строку в нём приходится собирать
арифметикой байтов, а не писать литералом.

Значит, разрыв выразительности живёт **не в длине**. Столбец «имён» — грубый
прокси: он считает все идентификаторы Go-функции, включая служебные (`err`,
`ReadFull`, `Write`), так что абсолютное число ни о чём не говорит. Говорит
контраст: у Go имена есть (8–13), у brainfuck — **ноль**, всегда, по устройству
языка.
В brainfuck нечем назвать ни ячейку, ни операцию: те же одиннадцать команд
сложения — это не «сложить a и b», это «занулить соседа, перекладывая единицы»,
и прочитать их можно только исполнив в голове. Коротко ≠ понятно. Мощность у
версий одна; Go тратит символы на то, чтобы дать вещам имена, — и это ровно то,
чего brainfuck не умеет и что делает язык языком.

## Версии

| | |
|---|---|
| Go | 1.26.3 |

Внешних зависимостей нет — только стандартная библиотека. Интерпретатор: лента
растёт вправо, ячейки — байты с переполнением по модулю 256, `,` на конце ввода
кладёт 0, парные скобки просчитаны заранее для прыжков за O(1).
