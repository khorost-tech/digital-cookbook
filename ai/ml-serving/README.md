# ml-serving

Онлайн-инференс модели серии на BentoML: цена сетевого хопа против вызова
в процессе, холодный старт, адаптивный батчинг, воркеры и GIL, и что
отдавать, когда модель не отвечает вовремя. Стенд к статье
[«Онлайн-инференс: латентность, батчинг и отказы»](https://khorost.tech/ai/ml-online-inference-serving/)
серии «Классический ML в проде».

## Повторение

Docker, Python 3, свободное место (не меньше 2 ГБ) и **десять ядер в
Docker**: сервис работает на ядрах 0–3 (`taskset`), генератор нагрузки —
шесть процессов на ядрах 4–9. Рядом должен лежать `../ml-dataset`.
Запуск из этого каталога: `FRESH=1 bash scripts/run-all.sh` — два раза.
Сравнение сессий: `python3 scripts/run-manifest.py compare fixtures/manifests/A.json fixtures/manifests/B.json`.
Контейнер без сети (`--network none`): сервис слушает 127.0.0.1 внутри
него. Образы — в `images.json`, Python-зависимости — `requirements.txt`
с хешами (`scripts/lock.sh`, отсечка `--exclude-newer 2026-10-03`).
Телеметрия BentoML выключена (`BENTOML_DO_NOT_TRACK=true`).

Версии: BentoML 1.4.39, scikit-learn 1.9.1, httpx 0.28.1.

## Что внутри

| файл | что |
|---|---|
| `stand/service.py` | сервис BentoML; окружение выбирает число воркеров, адаптивный батчинг (до 64 строк, бюджет задержки обработки пачки `max_latency_ms=20`) и искусственную задержку модели |
| `stand/measure.py` | оси опыта, генератор нагрузки, контроль его потолка |

Нагрузка — строки признаков дней 90–99 без пропусков (пропуск в JSON —
отдельный контроль), по одной строке на запрос.

## Проверки

| проверка | что мерит |
|---|---|
| `controls` | сервис отдаёт те же вероятности, что модель в процессе; строка не той ширины, нет поля, NaN в JSON |
| `service_vs_library` | запрос по HTTP против вызова в процессе, по одной строке |
| `cold_start` | отказы до готовности, доля загрузки модели во времени старта, память процессов против размера артефакта |
| `batching` | адаптивный батчинг при 1, 8 и 64 клиентах: успешные ответы в секунду, p99 успешных ответов, средняя пачка, отказы 503, доля запросов с ответом 200 не позже 100 мс (отказ — промах); потолок генератора |
| `workers` | 4 воркера против 1 при 64 клиентах без батчинга; потолок генератора |
| `degradation` | модель отвечает за 200 мс, клиент ждёт 50 мс: ноль вместо оценки, запасное правило, явная ошибка — против здоровой модели |

## Контракт опыта

`expected.json` записан до первого прогона; несовпадения пробы — в
`revision_after_probe` до сессий; проверки по рецензии — `revision_review2`,
прежние сводки — `fixtures/manifests-before-review2/`. Результат — `fixtures/checks.jsonl`,
точная команда в `cmd`, в конце COMPLETE. `python3 scripts/run-checks.py
<проверка>` повторяет опыт и выводит одну строку, не перезаписывая
фикстуру. Время и соотношения времени помечены `~`; в `actual` — только
пороговые признаки. Тесты держат ожидания независимо от `expected.json`;
диверсии ломают каждую проверку на копии стенда. Маркер ставит только
`run-marker.py`.

## Границы

Одна машина, Docker, сервис и генератор на разных ядрах одной VM;
абсолютные миллисекунды — не характеристика BentoML. KServe и Seldon Core
не проверялись. После согласованного коммита удалить `out/`.
