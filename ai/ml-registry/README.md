# ml-registry

Реестр моделей на MLflow с PostgreSQL и версионирование данных в DVC: что
на самом деле составляет версию модели, какая из частей переворачивает
решения, как артефакт переживает другую версию scikit-learn и почему
алиас в реестре — ещё не то, что обслуживается. Стенд к статье
[«Реестр моделей: версионирование того, что нельзя прочитать глазами»](https://khorost.tech/ai/ml-model-registry-versioning/)
серии «Классический ML в проде».

## Повторение

Docker, Python 3 и свободное место (не меньше 2 ГБ). Рядом должен лежать
`../ml-dataset` — датасет генерируется оттуда заново. Запуск из этого
каталога: `FRESH=1 bash scripts/run-all.sh` — два раза. Сравнение сессий:
`python3 scripts/run-manifest.py compare fixtures/manifests/A.json fixtures/manifests/B.json`.
Раннер поднимает сеть `ai-ml-registry-local`, PostgreSQL 18.6 (метаданные
MLflow), сервер MLflow (артефакты на его томе, клиент получает их через
сервер) и контейнер измерений; порты на хост не публикуются, в конце всё
удаляется. Образы — в `images.json`, Python-зависимости — `requirements.txt`
и `envs/*.txt` с хешами (`scripts/lock.sh`, отсечка `--exclude-newer 2026-10-03`).

Версии: MLflow 3.16.1, DVC 3.67.1, scikit-learn 1.9.1, skops 0.16.0; для
проверки версий библиотеки — отдельные окружения со scikit-learn 1.8.0,
1.7.2 и 1.6.1 (numpy тот же, 2.5.3).

## Что внутри

| файл | что |
|---|---|
| `stand/measure.py` | оси опыта: прогоны с параметрами и дайджестом среза данных, регистрация, алиасы и стадии |
| `stand/serve.py` | своё обслуживание: грузит модель по алиасу при старте и отдаёт `/loaded` — что загрузил |
| `stand/old_sklearn.py` | загрузка артефакта skops интерпретатором старого окружения |

Модель — та же, что в `../ml-dataset`; в MLflow она сохраняется в формате
по умолчанию (skops) с одним явно доверенным типом —
`sklearn.ensemble._hist_gradient_boosting.predictor.TreePredictor`.

## Проверки

| проверка | что мерит |
|---|---|
| `controls` | модель из реестра предсказывает как в памяти; несуществующий алиас; формат артефакта; сохранение без `skops_trusted_types` |
| `five_parts` | те же входы — те же предсказания и другие байты; срез данных, версия признака, препроцессинг вне артефакта и внутри пайплайна — перевёрнутые решения на днях 90–99 |
| `decision_policy` | та же модель и тот же вход, порог 1 % флагов по другому окну валидации — перевёрнутые решения |
| `library_version` | артефакт под scikit-learn 1.8.0, 1.7.2, 1.6.1: с тем же списком доверия и с типами scikit-learn из сообщения skops; предупреждения и совпадение предсказаний |
| `registry` | алиас; стадии и их предупреждение об устаревании |
| `stages` | алиас перенесён — что отдают запущенные `mlflow models serve` и своё обслуживание; `/version`; сверка «загружено против алиаса»; остаётся ли у прежней версии след алиаса (истории назначений реестр не хранит) |
| `data_versioning` | две версии датасета в DVC: кеш, указатели в git, откат и обучение из восстановленных байтов; тот же датасет прямо в git до и после gc |

## Контракт опыта

`expected.json` записан до первого прогона; несовпадения пробы — в
`revision_after_probe` до сессий; проверки по рецензии серии — в
`revision_review`, прежние сводки — в `fixtures/manifests-before-review/`. Результат — `fixtures/checks.jsonl`,
точная команда в `cmd`, в конце COMPLETE. `python3 scripts/run-checks.py
<проверка>` повторяет опыт и выводит одну строку, не перезаписывая
фикстуру. Время помечено `~`; сравнение сессий его исключает. Тесты держат
ожидания независимо от `expected.json`; диверсии ломают каждую проверку на
копии стенда. Маркер ставит только `run-marker.py`.

## Границы

Совпадение предсказаний под старыми scikit-learn — свойство этой модели и
этих версий, а не гарантия: предупреждение библиотеки прямо говорит
обратное. lakeFS не проверялся. После согласованного коммита удалить `out/`.
