# ml-features

Train/serve skew на PostgreSQL и Feast: один и тот же признак, посчитанный
батчем для обучения и онлайн при инференсе, расходится без единой ошибки.
Стенд меряет, насколько расходятся значения и решения модели, откуда
берётся расхождение, что из этого убирает feature store и что он вносит
сам. Стенд к статье [«Признаки в проде: feature store и train/serve skew»](https://khorost.tech/ai/ml-feature-store-and-skew/)
серии «Классический ML в проде».

## Повторение

Docker, Python 3 и свободное место (не меньше 2 ГБ). Рядом должен лежать
`../ml-dataset` — датасет генерируется оттуда заново. Запуск из этого
каталога: `FRESH=1 bash scripts/run-all.sh` — два раза. Сравнение сессий:
`python3 scripts/run-manifest.py compare fixtures/manifests/A.json fixtures/manifests/B.json`.
Раннер поднимает сеть `ai-ml-features-local`, PostgreSQL 18.6 и контейнер
с Python 3.12 и Feast; порты на хост не публикуются, в конце всё
удаляется. Образы — в `images.json`, Python-зависимости — `requirements.txt`
с хешами (`scripts/lock.sh`, отсечка `--exclude-newer 2026-10-03`).

Версии: Feast 0.66.0 (офлайн- и онлайн-хранилище — PostgreSQL), pandas
2.3.3, scikit-learn 1.9.1, numpy 2.5.3.

## Что внутри

| файл | что |
|---|---|
| `stand/db.py` | платежи в PostgreSQL; батч-признаки оконными функциями; состояние пользователя после каждого платежа — источник Feast; функция `features_before` для одного пути |
| `stand/online_team.py` | онлайн-путь по той же спецификации с тремя расхождениями прочтения: свой платёж в окне, календарные 30 дней, пропуск как ноль |
| `feast/repo.py` | сущность, представление `user_state` (ttl 7 дней), признаки по запросу `payment_features`, два источника счёта мошенничества |
| `stand/measure.py` | оси опыта |

Признаки — состояние **до** платежа: `tx_count_24h`, `amount_avg_30d`,
`minutes_since_prev`, `amount_ratio`; модель — `HistGradientBoostingClassifier`
из `../ml-dataset/gen/train.py`, порог — 1 % флагов на валидации.

## Проверки

| проверка | что мерит |
|---|---|
| `controls` | батч SQL против эталона генератора; сравнение ловит сдвиг на единицу |
| `skew` | онлайн-путь против батча на днях 90–99: доля расхождений по признакам, перевёрнутые решения, пойманное мошенничество, ошибки; расхождения выключаются по одному |
| `feature_store` | Feast онлайн (состояние пишется после каждого платежа) против офлайн-выборки Feast: отметка сущности равна времени платежа и на секунду раньше; ttl офлайн и онлайн; значение Feast против эталона «до платежа»; контроль онлайн-хранилища |
| `materialization` | материализация раз в 15 минут, час и сутки против записи каждого состояния |
| `point_in_time` | счёт мошенничества пользователя: снимок на день 90, PIT по времени платежа с самим платежом (собственная метка плюс задержанное знание) и строго по предыдущим (только задержанное знание), PIT по времени chargeback — AUC на валидации и в проде; PIT Feast против эталона |
| `one_path` | одна SQL-функция для обучения и инференса |

## Контракт опыта

`expected.json` записан до первого прогона; несовпадения пробы — в
`revision_after_probe` до сессий: что было дефектом обвязки и что
опровергло гипотезу; проверки по рецензии — `revision_review2`, прежние
сводки — `fixtures/manifests-before-review2/`. Результат — `fixtures/checks.jsonl`, точная команда в
`cmd`, в конце COMPLETE. `python3 scripts/run-checks.py <проверка>`
повторяет опыт и выводит одну строку, не перезаписывая фикстуру. Время
помечено `~`; сравнение сессий его исключает. Тесты держат ожидания
независимо от `expected.json`; диверсии ломают каждую проверку на копии
стенда. Маркер ставит только `run-marker.py`.

## Границы

Онлайн-путь с расхождениями написан для опыта: каждое расхождение
правдоподобно, но их набор подобран, а не найден в чужом коде. Время
вызовов (`~`) — одна машина, Docker, Python-SDK Feast с признаками по
запросу на pandas; это не характеристика Feast-сервера. После
согласованного коммита удалить `out/`.
