Замеры 1 и 2: ресурсы конвейеров и цена трансформации — свод
Дата: 2026-07-28/29
Железо: одна машина, прогоны строго последовательные, по одному конвейеру.
Сырые кадры: results/bench-*.csv, построчные итоги: results/bench-summary.txt

⚠ ЧИСЛА CPU — ПОРЯДОК ВЕЛИЧИНЫ, не бенчмарк. Они привязаны к этой машине,
этому потоку и этим конфигам. Сравнивать между конвейерами их можно только
потому, что вход, трансформация и набор полей на выходе у всех трёх
одинаковы — это проверяется scripts/compare-docs.sh, а не декларируется.

────────────────────────────────────────────────────────────────────────
ЗАМЕР 1. Ресурсы под нагрузкой

rate 5000 событий/с, 60 с, два повтора:

  конвейер     CPU под нагрузкой   RAM        CPU idle    RAM idle   потери
  fluentbit    4.7% / 5.7%         25 МиБ     0.0 / 0.1%  20-21 МиБ  0
  vector       12.0% / 12.1%       330-333    0.2 / 0.2%  146-155    0
  otelcol      34.2% / 33.2%       105-114    0.4%        42         0

  Прогоны otelcol r1 и r2 в bench-summary.txt сняты ДО исправления
  force_flush_period и дали расхождение -27 и -26 документов (разрезанные
  строки, см. results/10-line-split-probe.txt). Здесь взяты r3 и r4 — на
  исправленной конфигурации. CPU при этом изменился с 37.6/37.2 на 34.2/33.2,
  то есть в пределах разброса: разрезание строк ресурсов почти не стоило,
  оно портило данные.

rate 20000 событий/с, 60 с, два повтора:

  конвейер     CPU под нагрузкой   RAM        потери
  fluentbit    8.9% / 7.6%         25-26 МиБ  0
  vector       45.7% / 44.6%       470-478    0
  otelcol      93.4% / 94.7%       107-112    0

  Все три доставили 1 100 178 событий из 1 200 000 сгенерированных
  (разница — отсечённые запросы к /health), потерь нет ни у кого.

Разброс повторов: у Vector 0.8-2.4%, у Collector 1.4-2.9%, у Fluent Bit
до 15% — последнее на малых абсолютных значениях (4.7 против 5.7), где
доли процента дают большой относительный разброс.

Что видно:

  1. Fluent Bit дешевле обоих сразу по CPU и по памяти, с большим отрывом.
     При учетверении потока он прибавил в 1.6 раза — меньше всех.

  2. Между Vector и Collector — размен, а не превосходство. Vector втрое
     дешевле по CPU и вчетверо дороже по памяти. При 20000 ев/с Collector
     подошёл вплотную к полному ядру (94%), Vector занял меньше половины,
     но потребовал почти полгигабайта.

  3. Память Vector растёт с потоком (330 → 475 МиБ при учетверении), у
     Collector и Fluent Bit практически не меняется (105 → 110, 25 → 25).

  4. В простое все трое почти ничего не стоят, но Vector держит 150 МиБ
     против 40 у Collector и 20 у Fluent Bit. Для агента на каждом хосте
     это и есть настоящая цена присутствия.

ЗАМЕР 2. Цена трансформации (rate 5000, два повтора)

Сравнивается полный конвейер (парсинг + поле pipeline + отсечение /health)
против passthrough (строки уходят в бэкенд как есть).

  конвейер     passthrough CPU   full CPU        отношение
  vector       5.7% / 5.7%       12.0% / 12.1%   ×2.1
  otelcol      33.5% / 33.6%     34.2% / 33.2%   ×1.0 (в пределах разброса)
  fluentbit    2.3% / 2.1%       4.7% / 5.7%     ×2.4

  По памяти:
  vector       242 / 234 МиБ  →  333 / 330 МиБ   (+90 МиБ)
  otelcol       71 /  68      →  105 / 114       (+40 МиБ)
  fluentbit     25 /  25      →   25 /  25       (без изменений)

⚠ ВАЖНАЯ ОГОВОРКА, без которой эти числа врут.

  passthrough отправляет в бэкенд 300 000 документов, полный конвейер —
  275 141: он отсекает запросы к /health, то есть на 9% МЕНЬШЕ. Значит
  разница между колонками — это не чистая цена парсинга, а сумма двух
  разнонаправленных величин: парсинг и фильтрация добавляют работу, а
  сокращение потока на 9% её убавляет.

  Правильное чтение: полный конвейер обходится вдвое дороже passthrough
  У Vector и Fluent Bit ДАЖЕ С УЧЁТОМ того, что он отправляет меньше.
  Чистая цена парсинга, следовательно, ещё выше измеренной.

  У Collector разницы нет вовсе — на фоне его собственной стоимости
  обработки цена OTTL и фильтра теряется.

Что видно:

  1. У Vector и Fluent Bit разбор строк — основная статья расхода: он
     удваивает потребление CPU. У Collector он теряется в шуме, но не
     потому, что OTTL дешевле VRL, а потому что базовая стоимость самого
     конвейера втрое выше.

  2. Fluent Bit в режиме passthrough стоит 2.1-2.3% CPU — это близко к
     стоимости простого перекладывания байт, и именно с ней стоит сравнивать
     остальных, когда речь о «сколько стоит агент, который ничего не делает».

  3. Память на парсинг у Fluent Bit не растёт вообще, у Collector растёт
     умеренно, у Vector — заметнее всех.
