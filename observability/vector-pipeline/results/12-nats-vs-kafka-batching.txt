Почему агент на NATS дороже, чем на Kafka
==========================================

Снято 2026-07-28. Замер выполнен координатором отдельно от матрицы бенчмарка,
чтобы объяснить расхождение, замеченное в results/bench-summary.txt.

НАБЛЮДЕНИЕ ИЗ БЕНЧМАРКА
-----------------------
При одинаковом потоке 5000 событий/с CPU агента отличается вдвое:

  транспорт   CPU агента (два повтора)
  NATS        23.0%   24.1%
  Kafka       12.2%   13.2%

Разрыв ~2x лежит далеко за пределами разброса между повторами (2.8-8.2%),
то есть это не шум.

ГИПОТЕЗА
--------
NATS-синк публикует по сообщению на событие, Kafka-синк группирует события
в пакеты, поэтому на том же потоке делает на порядки меньше операций.

ПРОВЕРКА 1: документация Vector (структурное различие)
-----------------------------------------------------
Синк `nats`  — опций `batch` НЕТ вообще. Есть только управление на уровне
               запроса: request.concurrency, retry_*, rate_limit_*, timeout_secs.
Синк `kafka` — батчинг поддерживается: batch.max_events, batch.max_bytes,
               batch.timeout_secs со значением по умолчанию 1 секунда.
               То есть Kafka батчит, даже если batch не настроен явно.

ПРОВЕРКА 2: счётчик сообщений самого NATS-сервера (прямое измерение)
-------------------------------------------------------------------
В стенде у NATS включён монитор-порт (`-m 8222`). Запрос к /varz из контейнера
в той же сети compose:

  $ ./scripts/up.sh nats
  $ docker compose run --rm loadgen -rate 2000 -duration 10s
  2026/07/28 06:04:51 сгенерировано: nginx=10000 app=10000 total=20000

  $ docker compose run --rm --entrypoint sh loadgen \
      -c 'wget -qO- http://nats:8222/varz' | grep -E '"in_msgs"|"in_bytes"|"out_msgs"'
    "in_msgs": 10545,
    "in_bytes": 2842009,
    "out_msgs": 10545,

  $ docker compose exec -T aggregator sh -c 'wc -l < /archive/events.log'
  10545

ВЫВОД
-----
Сообщений принято сервером    10545
Событий доехало до архива     10545
Соотношение                   ровно 1:1

NATS-синк отправляет по одному сообщению на событие — подтверждено прямым
измерением, а не выведено из документации. Средний размер сообщения
2842009 / 10545 = 269 байт.

ГРАНИЦА ДОКАЗАННОСТИ (важно для статьи)
---------------------------------------
Сторона NATS измерена напрямую (1:1 подтверждено счётчиком сервера).
Сторона Kafka взята из документации: батчинг с таймаутом 1 с по умолчанию.
Число produce-запросов Kafka НЕ измерено — оно не видно из offsets (каждое
событие остаётся отдельной записью в топике, группировка происходит на уровне
запроса) и потребовало бы включения статистики librdkafka.

Поэтому корректная формулировка: разница в CPU объясняется отсутствием
батчинга у NATS-синка (измерено) в сочетании с наличием батчинга у Kafka-синка
(документировано). Утверждать конкретное число запросов Kafka нельзя.
