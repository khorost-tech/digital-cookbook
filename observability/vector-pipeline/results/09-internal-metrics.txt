Шаг 6: vector top / доступность GraphQL API агента
===============================================================================

Попытка 1 — как в брифе, без TTY:

$ timeout 8 docker compose exec -T agent vector top --url http://127.0.0.1:8686/graphql
2026-07-28T01:27:11.313322Z  INFO vector::app: Log level is enabled. level="info"
Terminal must be a teletype (TTY) to display a Vector dashboard.
(exit 0 — TUI отказывается рисоваться без реального терминала; проверено также на
заведомо нерабочем URL — сообщение об TTY выводится ДО попытки подключения, то есть
само по себе оно ничего не доказывает про доступность API)

Попытка 2 — TTY подделан через `script` внутри контейнера (у образа
timberio/vector:0.57.0-debian есть /usr/bin/script), терминалу явно задан размер
40x150 через `stty`, чтобы ratatui было куда рисовать (без stty `stty size` внутри
script давал "0 0" и TUI не мог рендериться содержательно):

$ docker compose exec -T agent script -qec \
    "stty rows 40 cols 150; vector top --url http://127.0.0.1:8686/graphql" /dev/null

TUI запустился, подключился по GraphQL и вживую рисовал таблицу компонентов
(поток ANSI-эскейпов захвачен и заново собран построчно с учётом cursor-addressing
через отдельный скрипт-интерпретатор, чтобы получить читаемый снимок экрана):

Это ЖИВОЙ снимок экрана TUI (статус "Connected", ненулевые счётчики после прогона
генератора) — TUI отработал корректно, строка "Terminal must be a TTY" из
Попытки 1 была именно про отсутствие терминала в неинтерактивном docker compose
exec -T, а не про недоступность API.

Дополнительное прямое подтверждение доступности GraphQL/REST API (на случай если
TUI-снимок сочтут непригодным как единственное доказательство — сделано изнутри
docker-сети стенда через ephemeral curlimages/curl, в обход хостового HTTP-прокси,
который на этом Windows-чекауте перехватывает POST на /graphql и подменяет ответ на
grpc-status:12/content-type:application/grpc — это артефакт корпоративного прокси
на хосте, не поведение Vector):

$ docker run --rm --network vector-pipeline_default curlimages/curl:latest \
    -s -w '\nHTTP:%{http_code}\n' --max-time 5 http://agent:8686/health
{"ok":true}
HTTP:200

$ docker run --rm --network vector-pipeline_default curlimages/curl:latest \
    -s -o /dev/null -w 'HTTP:%{http_code}\n' --max-time 5 http://agent:8686/playground
HTTP:200

Вывод: GraphQL API агента (api.enabled: true, 0.0.0.0:8686) доступен и рабочий —
подтверждено и вживую заснятым TUI, и прямыми запросами к /health и /playground.
