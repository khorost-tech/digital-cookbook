ВЫВОДЫ
------
Латентность. Разница между базовой линией и инструментированным вариантом лежит
на границе разброса: p50 4,7 против 4,9-5,0 мс (рост 0,2-0,3 мс), p90 12,1-12,2
против 12,3-12,9, p99 26,8-27,0 против 25,9-28,5. По p99 инструментированные
прогоны местами БЫСТРЕЕ базовых — то есть эффект меньше собственного шума стенда,
и утверждать «инструментирование замедлило на N процентов» по этим данным нельзя.
Честная формулировка: на этом профиле нагрузки (20 000 запросов, 8 параллельно,
цепочка Go -> Java -> PostgreSQL) цена инструментирования по латентности не
измеряется — она тонет в разбросе.

Единичный выброс: httpproto-1 дал max 5365 мс при p99 26,2 мс. Один запрос из
20 000 занял пять секунд, на перцентили это не повлияло. Во втором проходе того
же режима max = 51,8 мс. Причина не установлена; для вывода о протоколах это
значения не имеет, но замалчивать выброс неправильно.

CPU. Здесь эффект устойчив и виден по обоим повторам, у Java:
  java-backend без агента   49,6% и 58,7% (среднее по прогону, % одного ядра)
  java-backend с агентом    74,8% и 69,4% (gRPC), 60,4% и 68,9% (HTTP)
То есть агент прибавляет заметную долю CPU. У Go разница не выделяется из шума:
42,3 и 47,9 без SDK против 46,1 и 46,5 с SDK.

Память. У Go эффект чистый и повторяемый: 18,8-18,9 МиБ без SDK против 29,0-30,6
с SDK по gRPC и 26,0-26,1 по HTTP. То есть Go SDK стоит примерно 8-12 МиБ, и
gRPC-вариант дороже HTTP на 3-4 МиБ.
У Java память по этим данным сравнивать НЕЛЬЗЯ: базовая линия сама разошлась
между повторами вдвое (340,0 и 542,9 МиБ), и этот разброс шире, чем разница с
агентом (474-515 МиБ). Куча JVM растёт по своей логике; чтобы измерить вклад
агента, нужен фиксированный -Xmx и больше повторов — этого в замере не делалось,
поэтому вывода о памяти Java здесь нет.

gRPC против HTTP. По латентности неразличимо. По памяти Go-процесса gRPC дороже
на 3-4 МиБ (тянет свою реализацию транспорта). Практический вывод: выбор
протокола в этом стенде не про производительность, а про инфраструктуру —
пройдёт ли gRPC через промежуточные прокси и балансировщики.
